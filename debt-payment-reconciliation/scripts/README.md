# Скрипты проекта 02

Оба скрипта обезличены: в них нет рабочих путей пользователя, реальных названий организаций, банковских идентификаторов или реальных ИНН. В скрипте сверки уже заданы синтетические параметры, соответствующие опубликованному генератору тестовых файлов. При использовании собственного набора заменяйте их только синтетическими значениями.

## 1. Подготовка рабочей книги

Файл: `prepare_workbook.py`

Структура рядом со скриптом:

```text
scripts/
  prepare_workbook.py
  input/
    <один исходный Excel-файл>
  working/
    <одна целевая рабочая книга с листом data>
```

В каждой из папок `input` и `working` должен находиться ровно один файл Excel формата XLSX или XLSM. Скрипт переносит строку заголовков и данные, приводит значения столбцов J и L к числам, сортирует записи по столбцу B, скрывает заданные столбцы и пересчитывает сумму в L1. Дополнительный treemap выключен по умолчанию.

## 2. Сверка с банковскими платежами

Файл: `reconcile_bank_payments.py`

Структура рядом со скриптом:

```text
scripts/
  reconcile_bank_payments.py
  data/
    bank_1/
      <банковские выписки>
    bank_2/
      <банковские выписки>
    plan/
      <одна рабочая книга Excel>
```

В папке `plan` должен быть ровно один файл XLSX или XLSM. В нём необходим лист `data` с заголовками `Юрлицо`, `Дата оплаты по плану до`, `Долг по отгр`, `Город`. Для даты отчёта в имени файла должна присутствовать дата в формате ДД.ММ.ГГ, ДД.ММ.ГГГГ или ГГГГ-ММ-ДД.

Перед запуском откройте скрипт и настройте:

- `LEGAL_ENTITY_FILTERS` — названия организаций из тестовой книги, например `("КОМПАНИЯ 1", "КОМПАНИЯ 2")`.
- `COUNTERPARTY_INNS` — список ИНН контрагентов. Для опубликованного демонстрационного набора по умолчанию заданы синтетические значения `9900000001`, `9900000002`, `9900000003`; они соответствуют генератору из `test-data/`. Для другого тестового набора замените их на его синтетические ИНН.
- Папки `bank_1` и `bank_2` соответствуют организациям `КОМПАНИЯ 1` и `КОМПАНИЯ 2` в настройке скрипта. Если меняете названия папок, обновите соответствующую логику определения организации в `load_bank_rows()`.

Скрипт нормализует город из поля `Город`: удаляет начальный маркер `ОБЩИЙ` и завершающий маркер `СОСЕНКИ` (например, `ОБЩИЙ, МОСКВА-СОСЕНКИ` превращается в `МОСКВА`). В подготовленной рабочей книге значение в столбце `Город` заменяется очищенным названием города; в скрипте сверки применяется та же нормализация перед поиском и формированием сводных данных. Скрипт сопоставляет сумму группы с суммой одной банковской операции и ищет город из поля `Город` в назначении платежа. Несколько отдельных банковских списаний не суммируются. В лист `send` переносятся только группы с ровно одним найденным совпадением; неподтверждённые и неоднозначные группы остаются на `data`. Обновляется лист `total`.

## Зависимости и среда

- Python 3.10 или новее.
- `openpyxl`.
- `pywin32` для второго скрипта.
- Windows с установленным Microsoft Excel для выполнения Excel COM-операций во втором скрипте.

Установка:

```powershell
py -m pip install openpyxl pywin32
```

Запускайте скрипты из установленной среды Python. Перед первой проверкой используйте копии книг и синтетические данные. Скрипт создаёт резервную копию рабочей книги с суффиксом `_backup_before_reconcile`, только если такой файл ещё не существует; автоматически обновлять эту копию при следующих запусках он не будет. Для каждого повторного теста восстановите чистую книгу генератором либо самостоятельно сохраните отдельную копию. Закройте рабочую книгу в Excel перед запуском скрипта сверки.

## Важное предупреждение

Это публикация исходного кода, а не подтверждение готовности к эксплуатации на любых банковских форматах. Проверьте структуру заголовков, соответствие юридических лиц, тестовые ИНН, точность поиска города и суммы, резервное копирование и корректность итоговых листов на искусственных примерах. Не загружайте в публичный репозиторий реальные выписки или рабочие книги.
