# Алгоритм и технические решения

## Последовательность обработки

1. Найти рабочую книгу платёжного плана.
2. Загрузить банковские файлы из настроенных каталогов.
3. Для каждой выписки определить строку заголовков и позиции значимых полей.
4. Отобрать банковские операции, соответствующие настроенным фильтрам.
5. Найти на листе плана заголовки необходимых полей.
6. Сгруппировать строки плана по ключу: юридическое лицо + плановая дата + расчётный счёт.
7. Рассчитать сумму задолженности каждой группы с использованием Decimal.
8. Сопоставить группу с банковскими операциями по юридическому лицу, сумме с допустимым отклонением и городу в назначении платежа.
9. При единственном кандидате перенести строки группы в реестр результатов.
10. При отсутствии или множественности кандидатов сохранить группу в исходном наборе.
11. Обновить сводный лист и пересчитать показатели.
12. Сохранить изменения с использованием Excel COM, чтобы сохранить VBA-проект книги XLSM.

## Точность сумм

Для финансовых сумм используется Decimal и допустимое отклонение до одной копейки. В демонстрационной реализации это правило должно быть явно покрыто тестами.

## Защита от повторной обработки

Перед переносом проверяется наличие группы в листе результатов. Механизм сравнения ключей должен использовать единую нормализацию юридического лица, даты и расчётного счёта; это отдельный пункт проверки перед публикацией.

## Технические вопросы перед выпуском публичного кода

- Вынести названия юридических лиц, ИНН, банковские каталоги и фильтры в конфигурацию с синтетическими значениями.
- Проверить полноту и корректность сопоставления ИНН контрагента с группой плана.
- Заменить частичное совпадение названий городов на более строгую токенизацию/справочник.
- Унифицировать нормализацию ключей при поиске уже обработанных групп.
- Проверить резервное копирование при повторных запусках.
- Проверить формулы итогового листа на ложные совпадения по подстроке.
- Добавить определение/тестирование функции разбора даты, используемой при работе с Excel COM.
- Подготовить синтетические fixtures для различных форматов банковских выписок и случаев: одно совпадение, отсутствие совпадения, неоднозначность, повторный запуск, дробление платежа.

## Сохранение XLSM

Промежуточная обработка выполняется библиотекой openpyxl, а перенос подготовленных диапазонов в исходную книгу — через Excel COM. Это сделано для сохранения VBA-проекта исходной книги. Поведение следует проверять на копиях тестовых файлов с макросами.
