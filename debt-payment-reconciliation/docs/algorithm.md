# Алгоритм и технические решения

## Последовательность обработки

1. Найти единственную рабочую книгу XLSX/XLSM в каталоге `data/plan`.
2. Загрузить файлы банковских выписок из каталогов `data/bank_1` и `data/bank_2`.
3. Для каждой выписки определить строку заголовков и позиции даты, дебета, ИНН контрагента и назначения платежа. Поддерживаются распознаваемые двуязычные и русскоязычные заголовки; для прежнего широкого формата предусмотрены резервные позиции столбцов.
4. Отобрать операции с датой, суммой и назначением, ИНН которых соответствует списку `COUNTERPARTY_INNS`.
5. На листе `data` найти поля юридического лица, плановой даты оплаты, города и суммы долга.
6. Сгруппировать строки плана по юридическому лицу, плановой дате оплаты и значению поля `Город`.
7. Рассчитать сумму каждой группы с использованием `Decimal`.
8. Проверить, не присутствует ли группа уже на листе `send`. Уже перенесённая группа повторно не добавляется.
9. Для оставшихся групп найти банковские операции того же юридического лица, с совпадающей суммой (допуск — 0,01) и городом из поля `Город` в назначении платежа.
10. Перенести группу в `send`, только если найден ровно один кандидат. Если кандидатов нет или их несколько, оставить группу на `data`.
11. Физически удалить из `data` строки успешно перенесённых групп и обновить лист `total`.
12. Сохранить книгу. Для XLSM используется Excel COM / pywin32, чтобы сохранить VBA-проект; перед сохранением создаётся резервная копия, если файл резервной копии с таким именем ещё не существует.

## Правила сопоставления

- Ключ группировки: юридическое лицо + плановая дата оплаты + расчётный счёт.
- Сумма банковской операции сравнивается с суммой всей группы с точностью до копейки.
- Несколько отдельных банковских списаний не складываются для подтверждения одной группы.
- Дата фактической банковской операции может отличаться от плановой даты.
- Город ищется в назначении платежа по нормализованному значению поля `рс`. Для составных названий допускается совпадение по значимым частям строки.
- При нескольких подходящих банковских операциях алгоритм не выбирает одну произвольно: группа остаётся на ручную проверку.
- Повторное добавление группы, уже находящейся на листе `send`, предотвращается проверкой существующего реестра.

## Параметры демонстрационного запуска

В `reconcile_bank_payments.py` заданы синтетические значения для опубликованного генератора:

- `LEGAL_ENTITY_FILTERS`: `КОМПАНИЯ 1`, `КОМПАНИЯ 2`;
- `COUNTERPARTY_INNS`: `9900000001`, `9900000002`, `9900000003`;
- каталоги выписок: `bank_1` и `bank_2`.

Эти параметры соответствуют только демонстрационным книгам из `test-data/generate_test_data.py`. Для собственного тестового набора замените их синтетическими значениями. Реальные ИНН, названия организаций и банковские реквизиты не следует добавлять в публичный репозиторий.

## Ограничения и контрольные меры

- Частичное совпадение города в назначении платежа — эвристика; на новых форматах выписок её необходимо проверять на тестовых примерах.
- Сопоставление по сумме и тексту назначения формирует кандидата на подтверждение, но не заменяет проверку финансового специалиста.
- Несколько отдельных списаний не агрегируются.
- Резервная копия с суффиксом `_backup_before_reconcile` создаётся только при её отсутствии. При повторных тестах необходимо восстановить исходную чистую книгу из генератора либо отдельно сохранить новую копию до запуска; существующая резервная копия автоматически не перезаписывается.
- Для сохранения XLSM используется Excel COM / pywin32; второй скрипт требует Windows и установленный Microsoft Excel.

## Сохранение XLSM

Промежуточная обработка выполняется библиотекой openpyxl, а сохранение изменений в книге XLSM — через Excel COM. Такой подход используется для сохранения VBA-проекта исходной книги. Поведение следует проверять на копиях тестовых файлов с макросами.
