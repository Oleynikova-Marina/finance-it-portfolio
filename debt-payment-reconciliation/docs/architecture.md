## Компоненты

| Компонент | Назначение |
|---|---|
| Платёжный план Excel | Исходные обязательства и строки задолженности |
| Модуль подготовки данных | Перенос данных плана в рабочую книгу, подготовка листа data |
| Загрузчик банковских выписок | Чтение файлов из двух настроенных каталогов |
| Парсер выписок | Определение заголовков и полей банковских операций |
| Фильтр операций | Отбор операций по заданным признакам |
| Модуль группировки | Объединение строк плана по юридическому лицу, плановой дате и расчётному счёту |
| Модуль сопоставления | Поиск единственной банковской операции по сумме и признаку города в назначении |
| Лист send | Реестр групп с найденным однозначным соответствием |
| Лист data | Исходные и пока не подтверждённые группы |
| Лист total | Сводная аналитика по городам |
| Excel COM | Перенос результатов в исходную XLSM-книгу с сохранением VBA-проекта |

## Потоки данных

1. Скрипт подготовки переносит данные платёжного плана в лист data рабочей книги.
2. Скрипт сверки отдельно загружает банковские выписки из двух каталогов.
3. Данные плана группируются по трём полям: юридическое лицо, плановая дата оплаты и расчётный счёт.
4. Для каждой группы вычисляется общая сумма задолженности.
5. Банковские операции проверяются на соответствие настроенным фильтрам; затем выполняется поиск кандидата по юридическому лицу, сумме и городу в назначении платежа.
6. Только группа с ровно одним кандидатом переносится в send; при нуле или нескольких кандидатах она остаётся в data.
7. Пересчитывается сводная аналитика на листе total.
8. Изменения сохраняются в рабочей книге. В текущей реализации для сохранения исходной XLSM-книги используется Excel COM.

## Границы автоматизации

- Система формирует кандидатов на подтверждение оплаты по заданным правилам, а не заменяет финансовый контроль.
- Неоднозначные и ненайденные совпадения остаются на проверку специалисту.
- В текущей логике несколько банковских списаний не суммируются для подтверждения одной группы задолженности.
- Дата фактической банковской операции может отличаться от плановой даты группы.
- Перед публичным использованием архитектура и правила должны быть проверены на синтетических данных.

## Условные обозначения

- **Входы:** платёжный план и банковские выписки.
- **Обработка:** подготовка, разбор, фильтрация, группировка и сопоставление.
- **Результаты:** реестр найденных оплат, список на проверку и сводная аналитика.
- **Контроль:** резервная копия и финальная проверка специалистом.
